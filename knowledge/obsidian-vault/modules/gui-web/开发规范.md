# GUI Web 控制台 开发规范

## 模块开发规范

- 保持 UI 与业务分离：新增窗口先定义 API/DTO，再接前端状态。
- 所有真实输入入口默认 `execute=false`，需要可见状态灯、审批和审计。
- 会话、聊天室、附件、记忆必须按 workspace/session 隔离。
- 新增用户可见交互需真实前端 + computer-use 或截图证据验收。

## UI 缩放设计检查点（16:9 舞台，2026-06-19 立）

> 背景根因：`.ui-redesign` 16:9 舞台用 `min(100vw,100vh*16/9)` 自适应（letterbox），内部宏观布局用 % 能等比；
> 但叶子组件用 `clamp(px, Xvw, px)`（参照**视口** vw + px 上下限）+ 固定 px（dock 宽/gap/标题宽），
> 且定义了 `--design-width/height:1920/1080` 却**无任何 `transform: scale()` 接线**。视口非 16:9 或变小时，
> 组件参照系（视口）与舞台真实缩放发散 → "组件不跟随比例缩放"。详见 `tmp/ui-scale-rootcause-analysis.txt`。

后续任何 UI 修改/新增组件必须遵守：
1. **舞台内尺寸一律相对【舞台】**，禁止裸用 `vw/vh`（其参照视口，≠ letterbox 后的舞台真实尺寸）。
2. **优先"设计画布 + 单一缩放"**：内部按设计 px@1920×1080 布局，对舞台施加 `transform: scale(var(--ui-scale))`，
   `--ui-scale = min(100vw/1920, 100vh/1080)` 随 resize/ResizeObserver 重算并居中；让全部元素统一等比。
3. **避免对舞台内尺寸用带 px 上下限的 `clamp()`**（上下限会在极端尺寸破坏等比）。
4. 固定 px（dock 宽、gap、标题宽等）须换算为设计 px 并纳入统一缩放，不得游离于缩放体系外。
5. **极端窗口自检**：新增/改动组件后，在小窗、高窄、宽扁三种极端窗口下肉眼确认仍等比对齐，方可验收。

## 项目级通用规范

- 新增业务配置进入 `coolzhu.toml` 或模块配置文件；不得扩散 `COOLZHU_*` / `CLAW_*` 自定义业务环境变量。
- GUI 只做 API client，不直接承载 core-runtime、vision、computer-use 的业务细节。
- 真实键鼠输入默认关闭，必须有显式授权、dry-run/证据链和审计。
- 跨模块接口变更先改对应 `INTERFACE.md`，删除字段必须先 deprecated。
- 用户可见功能验收必须启动真实前端，并观察可见反馈；HTTP/API 测试只能作辅助证据。
- 修改高风险链路时按规范备份、设置命令超时，并把验证结果写入 work-log。

## 验证原则

- 修改后运行对应模块的 `cargo check/test --offline`；用户可见功能还要真实前端或截图证据。
- 工作日志记录：修改目的、涉及模块、验证命令、结果、风险与回滚方式。
