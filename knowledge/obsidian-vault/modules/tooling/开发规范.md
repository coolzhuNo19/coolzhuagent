# Tooling / MCP / 插件 开发规范

## 模块开发规范

- 工具 schema、名称、超时语义变化必须同步 GUI 工具调用区和接口文档。
- 真实执行工具必须给 dry-run 或风险说明，DangerFullAccess 需要审批和审计。
- 工具原始 input 不得直接写日志/SSE，只输出 input_summary 白名单。
- MCP server 配置 key/secret 走 env 或本地安全配置，不写入 query 或 vault。

## 项目级通用规范

- 新增业务配置进入 `coolzhu.toml` 或模块配置文件；不得扩散 `COOLZHU_*` / `CLAW_*` 自定义业务环境变量。
- GUI 只做 API client，不直接承载 core-runtime、vision、computer-use 的业务细节。
- 真实键鼠输入默认关闭，必须有显式授权、dry-run/证据链和审计。
- 跨模块接口变更先改对应 `INTERFACE.md`，删除字段必须先 deprecated。
- 用户可见功能验收必须启动真实前端，并观察可见反馈；HTTP/API 测试只能作辅助证据。
- 修改高风险链路时按规范备份、设置命令超时，并把验证结果写入 work-log。

## 验证原则

- 修改后运行对应模块的 `cargo check/test --offline`；用户可见功能还要真实前端或截图证据。
- 工作日志记录：修改目的、涉及模块、验证命令、结果、风险与回滚方式。
