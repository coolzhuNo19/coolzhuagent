# COOLZHU 总需求导航

## 需求管理表

| REQ/主题 | 状态 | 迁移摘要 |
| --- | --- | --- |
| 第一梯队 | 主体已完成/少量补洞 | Web-GUI 卡片、多窗口、会话/聊天室、模型配置、上下文装配。 |
| 第二梯队 | 主体完成/边界收口 | Core Runtime 与分层 beads 记忆系统。 |
| 第三梯队 | 主体完成/真实场景回归 | Vision Tool Service、Grounding Router、Computer Use。 |
| 第四梯队 | 够用维护 | GUI Desktop、桌宠、TTS/STT。 |
| 第五梯队 | 冻结/待评估 | 打包迁移、CLI、运维稳定性。 |

## 状态口径

| 状态 | 定义 |
| --- | --- |
| 已完成 | 已实现并通过基础验证。 |
| 测试中 | 代码已完成，仍需自动化、矩阵或真实交互验证。 |
| 待交互验证 | 方案或代码就绪，剩余真实窗口/硬件/人工确认。 |
| 开发中 | 已开始实现，仍有功能缺口。 |
| 待开发 | 需求确认但尚未实现。 |
| 冻结 | 当前不实现，只保留方案和风险记录。 |

## 更新规则

- 新需求先入需求表，再补方案、实现、验证、work-log 和状态回写。
- 需求状态不得只停留在口头计划；验证不充分时使用“测试中/待交互验证”。
