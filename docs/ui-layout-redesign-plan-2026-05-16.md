# 2026-05-16 Web GUI 16:9 多窗口重构方案

## 目标

后端/API 主体闭环后，前端布局进入最高优先级。新架构以 1920x1080、16:9 为主设计基准，保留 UI 中间大部分空间可重复使用，减少卡片碎片化，把现有能力收束成可折叠/展开的多窗口工作台。

## 当前后端未实现或待验证功能

### 已有后端能力但仍需交互验证

- `REQ-WEB-CHAT-007`：多 Agent handoff 后端/API/tool 已完成，仍需真实 UI 中验证成员条、任务链抽屉、手工转交入口。
- `REQ-LLM-005`：Custom OpenAI-compatible 后端/API 已完成，仍需真实本地模型或中转 endpoint 验证。
- `REQ-DESK-PET-003`：桌宠状态联动后端/API 已完成，仍需真实 Tauri 桌宠窗口验证。

### 布局重构会暴露的后端缺口

- 工程目录窗口：
  - 目录树已有基础能力，但缺 UI 专用的文件内容读取、保存草稿、二进制预览保护和大文件分页策略。
  - 缺 diff view 专用 API，可先复用 git diff / 文本 diff 只读生成，再考虑编辑。
- 设置窗口：
  - 会话、Provider、模型、工具、诊断 API 已有，但配置项分散。
  - 需要一个聚合配置读取/保存契约，把旧三合一卡片、工具审批、测试实验室、音频、视觉 profile 统一进同一设置窗口。
- 聊天室窗口：
  - 聊天、上下文、handoff、附件主体已有。
  - 需要为新布局补 50 行以上稳定可读的虚拟滚动/分页策略，避免长历史拖慢主线程。
- 浏览器窗口：
  - 当前没有完整网页浏览器后端。
  - 若只做搜索/展示，可以先用前端 WebView/iframe + 外部打开兜底；若要自动化浏览器操作，需要后端会话、导航、截图、DOM/可访问性桥接。
- 多媒体播放器窗口：
  - 附件索引、文件服务、消息内媒体预览已有。
  - 缺完整播放器库：播放列表、媒体元数据、最近播放、图片/视频浏览模式、音频队列。
- 终端窗口：
  - 已有工具化 bash/PowerShell 执行与审计。
  - 缺交互式 PTY/WebSocket 终端；需要严格复用工具权限、时间授权和审计，不做绕过。
- 3D 状态场景：
  - 可从 `/api/state`、`/api/pet/state`、`/api/tools/events`、聊天室 SSE 拼装状态。
  - 缺一个统一 Agent 活动流 API；首版可前端聚合，后续再加 `/api/agents/activity`.

### 已裁剪或冻结

- 安装包、资源加密、完整性校验：全部冻结。
- 外视觉：删除。
- 双视觉模型常驻、ShowUI 生命周期托管、内视觉持续监控、关键词触发：删除。
- 语音监控/唤醒词：不保留；音频只保留 TTS/STT。
- 桌宠：当前功能够用，不新增需求，只保留 bugfix 和交互验收。

## 布局总体结构

### 画布

- 基准分辨率：1920x1080。
- 长宽比：16:9。
- 分区：上下两大区。
- 上区高度：控制在 20%~30%，默认锁定为 24%，即约 259px。
- 下区高度：控制在 70%~80%，默认锁定为 76%，即约 821px，优先保证多窗口工作区和 3D 状态场景空间。

### 上区

- 中间：Logo 和品牌标题，保留 Mario / FC 像素风格。
- 左侧：Agent 总览卡片，宽度约 15%，显示已激活 Agent、视觉 Agent、聊天室数、模型连接状态。
- 右侧：任务卡片，宽度约 15%，显示当前任务队列、handoff 状态、工具审批待处理数。
- 中央剩余区域：用于 Logo、项目状态、当前 workspace 和简短系统提示。

### 下区

- 多窗口复用区。
- 每个窗口都有左侧标题栏。
- 双击窗口左侧标题栏可折叠/展开。
- 展开一个窗口时，其它窗口自动折叠为左侧标题栏。
- 所有窗口折叠后，下部分展开区域可用于显示 3D 动画状态场景。
- 折叠标题栏可以带图标、状态点、未读/待处理数量。

## 3D 状态场景

- 场景：FC 游戏像素小人办公室。
- 风格：Mario 风格、像素砖块、管道、问号砖、工作台、终端、文件柜。
- 角色：多个像素小人代表会话 Agent。
- 状态表现：
  - idle：坐在工位待命。
  - thinking：头顶冒思考气泡或敲键盘。
  - tool：走向工具台或终端。
  - success：金币/星星效果。
  - warning：问号砖或感叹号提示。
- 技术建议：
  - 先用 CSS/Canvas/Three.js 做非阻塞背景层。
  - 所有窗口折叠时全屏显示，窗口展开时只保留轻量背景。
  - 不在首轮做复杂物理和游戏交互，避免影响主工作台性能。

## 视觉风格

- 继续保留 Mario / FC 像素主题。
- 从“许多小卡片”转为“桌面工作台 + 可折叠窗口”。
- 避免营销式 hero、装饰性大卡片和一屏内过多说明文字。
- 主要信息密度要高，适合长时间工作。
- 卡片圆角不超过 8px，按钮和工具优先使用图标。
- 颜色避免单一深蓝/紫色主题，保留金色像素边框但增加灰黑、砖红、草绿、天空蓝等分层。

## 布局锁定与素材清单

- 布局比例锁定：上下两区，上区 20%~30%，下区 70%~80%，默认按 24% / 76% 实现。
- 顶部素材：
  - Logo / 品牌标题背景图。
  - Agent 总览卡片框、任务卡片框。
  - 紧凑状态行图标和计数徽标。
- 下区窗口素材：
  - 折叠标题栏图标：工程目录、设置、聊天室、浏览器、多媒体播放器、终端、任务/授权、记忆/知识、视觉实验室、诊断日志。
  - 展开窗口框：左侧标题栏、窗口内容背景、可滚动边框、状态角标。
  - 通用组件：像素按钮、输入框、选择器、分段控制、开关、工具审批按钮、附件按钮、发送按钮。
- 背景素材：
  - 所有窗口折叠后下部分区域显示的 FC 像素小人办公室 3D 动画背景。
  - 日志/诊断窗口背景纹理，要求低对比、可读性优先，不干扰日志文本。
- 生成策略：先用 imagegen 生成一张资产板，确认图标语言、组件边框和背景方向，再切分到前端实现。

## 风险评估

- 高风险：一次性重写全部前端可能破坏已验证 API 交互。建议先做静态布局原型，再逐个窗口接入旧功能。
- 中风险：终端窗口需要 PTY/WebSocket 和权限闸门深度绑定，不能直接暴露裸 shell。
- 中风险：浏览器窗口如果内嵌网页，会受到 CSP、登录态、跨域和 WebView 安全限制。
- 中风险：3D 状态场景可能抢性能，必须可降级为静态像素场景。
- 低风险：设置窗口聚合现有 API，可先把旧三合一卡片能力迁移进去。

1. D1 布局骨架：已完成。备份旧 Web UI，建立上下两区、顶部总览/任务/Logo、下区多窗口 dock、窗口折叠/展开、全折叠 3D 场景占位；删除外视觉与语音监听入口，保留 TTS/STT。

3. D2 功能迁移：把现有聊天室、输入条、附件、handoff、会话配置、工具审批、内视觉、测试实验室迁入对应窗口，保持既有 data-role/API 契约可用。
4. D3 工程目录窗口：文件树 + 只读文件内容 + diff view。
5. D4 设置窗口深化：模型、工具、诊断、音频、视觉 profile、测试配置统一分区。
6. D5 任务链/审批窗口：从聊天区剥离，做成独立折叠窗口，并展示授权剩余时间。
7. D6 多媒体播放器窗口：先接附件索引和本地预览。
8. D7 浏览器窗口：先做搜索/展示，再评估自动化能力。
9. D8 终端窗口：最后做，必须先确定 PTY 权限与审计方案。
