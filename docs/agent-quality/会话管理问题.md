# 会话管理问题库

## 2026-06-26：委托 GLM5.2 执行 demo 时出现脚本编码导致的会话消息乱码

### 现象

使用 `tmp/run-glm52-2d3d-demo.ps1` 创建聊天室、上传角色定装图并委托 GLM5.2 执行 2D→3D demo 时，Web Console 收到的用户提示与模型回复主体出现 mojibake 乱码。日志中 JSON 可被重新按 Latin-1→UTF-8 解码，但对会话界面和模型执行过程而言，原始上下文已经被污染。

相关文件：

- 脚本：`C:\Users\zhupu\Desktop\codex\tmp\run-glm52-2d3d-demo.ps1`
- 结果：`C:\Users\zhupu\Desktop\codex\tmp\logs\glm52-2d3d-demo-20260626-221249.json`
- 驱动日志：`C:\Users\zhupu\Desktop\codex\tmp\logs\2026-06-26-run-glm52-2d3d-demo-driver-utf8.log`

### 根因

Windows PowerShell 5.1 对无 BOM UTF-8 `.ps1` 源文件容易按系统 ANSI codepage 解释，导致中文提示在脚本源码读取阶段即损坏。虽然后续 HTTP 请求已改为 UTF-8 bytes 发送，但损坏发生得更早。

### 约束

后续所有涉及中文提示、会话创建、模型委托的 PowerShell 临时脚本必须满足其一：

1. 使用带 BOM 的 UTF-8 文件；
2. 使用 `pwsh` 并显式设置 `[Console]::OutputEncoding = [Text.UTF8Encoding]::UTF8`；
3. 将中文 payload 写入 `.json` 文件，再由脚本按 UTF-8 bytes 读取发送；
4. 执行前用本地回读/HTTP echo 验证会话消息没有乱码。

### 后续 SKILL 约束候选

- 会话任务启动前先创建“干净聊天室”，显式锁定目标会话与目标模型。
- 模型收到的第一条用户消息必须在日志中可读；若不可读，应立即中止任务，不允许继续执行。
- 长任务结果必须落到指定聊天室，不能只依赖进程日志。
