# 会话链路问题库

## 2026-06-26：本地模型与视觉服务需要跟随 Web Console 生命周期关闭

### 现象

用户关闭或重启 `coolzhu-agent` 后，本地模型相关服务可能残留监听端口，导致后续启动出现幽灵端口、ShowUI/UI-DETR 状态与前端开关不一致、Web Console 偶发无法正常拉起。

### 根因

`coolzhu-web-console` 用 `spawn_detached` 启动 UI-DETR/ShowUI 等本地模型服务时，部分子进程没有被纳入 `windows-process-guard` Job Object。ShowUI 早期还通过 `start-local-vlm.ps1 -Profile showui -Background` 二次后台化，实际 Python listener 会逃逸 Web Console 生命周期。

### 已实施修复

当前 `modules/gui-web/packages/web-console/src/main.rs` 已包含：

- Web Console 退出时调用 `shutdown_local_model_services_on_exit()`；
- `spawn_detached` 启动子进程后执行 `local_model_child_job()?.assign(&child)`；
- ShowUI 启动去掉 `-Background`，保持 wrapper 与子进程可被 Job Object 管理；
- 退出清理端口：`8082`、`7860`、`8000`、`8081`。

### 约束

- 不得用猜测的 health route 判断链路健康；本轮 `/api/local-model/status` 返回 404，说明路由必须以源码或已登记 API 为准。
- 视觉与本地模型服务必须提供“启动、状态、关闭、端口归属”的统一自检数据。
- 后续新增本地服务时，必须加入退出清理端口集合或 Job Object 绑定测试。
