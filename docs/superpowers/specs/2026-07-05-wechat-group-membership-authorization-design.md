# 微信群成员识别与 ClawBot 操作授权设计

日期：2026-07-05

## 1. 目标

在现有“微信连接”能力上补齐微信群场景：

- 在“微信连接”窗口显示 ClawBot 已发现并确认加入的群。
- 从真实 iLink 入站事件逐步识别群和发言成员。
- 为每个已识别成员设置“操作员 / 聊天成员 / 无权限”三档权限。
- 为每个登录的 ClawBot 微信账号绑定一个独立的“ClawBot 操作管理员”。
- 群消息只有明确 `@ClawBot` 后才允许进入权限判断和模型调度。
- ClawBot 被移出群后清理该群的绑定、成员授权和待发送记录。
- 所有权限结果、失败原因和清理动作均可审计，且不触发递归重试。

这里的“操作管理员”是 ClawBot 的操作管理员，不等同于微信群主或微信群管理员。

## 2. 协议能力边界

腾讯 iLink 当前公开消息协议可以提供 `group_id` 与 `from_user_id`，但没有群列表、完整群成员名册、邀请入群或主动退群接口。因此采用事件驱动同步：

- `group_id` 是微信群稳定身份。
- 群消息中的 `from_user_id` 是当前消息发送成员身份。
- 只有发过消息或出现在可验证系统事件中的成员才会进入“已识别成员”列表。
- 不承诺展示从未发言的完整微信群成员名册。
- 不以“长时间没有消息”推断退群，避免误删正常群。

群的移入和移出均由操作管理员在手机微信中完成。coolzhu 不模拟手机微信的群管理动作。

## 3. 角色与能力

### 3.1 ClawBot 操作管理员

每个登录的 ClawBot 微信账号只能绑定一个操作管理员微信联系人。该身份在本地“微信连接”窗口认领、撤销或更换，不提供 `/claim` 命令。

操作管理员具有：

- 对话回复；
- 状态查询；
- 工具调用；
- 文件读写；
- 任务控制；
- 审批处理；
- 群绑定和成员角色管理；
- 群解除与数据清理。

操作管理员的能力仍与目标聊天室授权取交集，不能绕过聊天室的 `read-only / workspace-write / full-access` 边界。

### 3.2 操作员

操作员具有：

- 对话回复；
- 状态查询；
- 工具读写；
- 文件读写。

操作员没有任务控制、审批处理、绑定管理和成员授权能力。

### 3.3 聊天成员

聊天成员仅具有自然语言对话回复能力，不具有文件、工具、任务、审批或绑定管理能力。

### 3.4 无权限

新识别群成员默认是“无权限”。其消息不调度模型或工具；明确 `@ClawBot` 时可以返回限流的无权限提示，未 `@ClawBot` 时静默忽略。

## 4. 身份识别与数据流

### 4.1 入站标准化

provider 收到 `getupdates` 消息后执行以下标准化：

1. 从 `group_id` 及兼容字段解析群 ID。
2. 从 `from_user_id` 及兼容字段解析实际发送成员 ID。
3. 用 `(account_id, group_id, member_id)` 建立成员唯一键。
4. 使用 `message_id` 或稳定请求指纹去重。
5. 只持久化鉴权必需的身份、时间和状态，不把完整群消息正文写入成员档案。

当前解析器在群消息分支没有使用官方 `from_user_id` 作为成员 ID 兜底，实施时必须修正，并用官方字段形态建立回归测试。

### 4.2 群记录

首次收到带群身份的真实入站事件时创建或刷新群记录：

- `account_id`
- `group_id`
- `group_name`（协议提供时使用，否则显示脱敏 ID）
- `first_seen_at_ms`
- `last_seen_at_ms`
- `lifecycle_state`
- `sync_evidence`
- `chat_room_id`
- `default_session_id`

群状态为：

- `awaiting_confirmation`：已有配置，但还没有真实群事件确认。
- `active`：最近真实事件确认 ClawBot 可接收该群消息。
- `sync_limited`：provider 在线，但协议无法主动确认当前群列表或移出状态。
- `removed`：收到明确移出证据并已完成清理。

### 4.3 成员记录

每次群消息都会 upsert 已识别成员：

- `member_id`
- `member_name`（协议提供时使用，否则显示 ID）
- `first_seen_at_ms`
- `last_seen_at_ms`
- `role`
- `enabled`
- `source`

操作管理员身份按 `(account_id, administrator_peer_id)` 单独存储，不作为微信群管理员，也不复制成每个群的普通成员授权。操作管理员在任一群中被识别为消息发送者时，运行时计算其管理员能力。

### 4.4 @ClawBot 判定

优先使用 provider 提供的明确 mention 字段；没有结构化字段时，只接受经过空白字符归一化后的明确 `@名称` 前缀。可识别名称由登录账号信息和页面配置共同维护。

无法可靠确认 `@ClawBot`、成员 ID 或群 ID 时采用 fail-closed：只记录脱敏诊断事件，不调度模型、工具或命令。

## 5. “微信连接”窗口

### 5.1 操作管理员区域

- 显示当前登录账号和已绑定操作管理员。
- 从已识别私聊联系人中选择联系人。
- 提供“设为操作管理员”“撤销”“更换”操作。
- 没有可选联系人时提示先向 ClawBot 发送一条私聊消息。
- 本地界面是认领的唯一入口，不提供微信命令行认领。

### 5.2 已加入的群

每个群卡片显示：

- 群名称或脱敏 ID；
- 加入/同步状态；
- 首次发现和最后事件时间；
- 已识别成员数；
- 当前绑定聊天室与模型会话；
- 最近同步证据与协议限制说明。

页面明确标注“已识别成员”，不使用“完整群成员”措辞。

### 5.3 成员权限

选择群后显示已识别成员列表。每个成员可以切换：

- 操作员；
- 聊天成员；
- 无权限。

操作管理员在列表中以锁定标识显示，不允许被普通角色设置覆盖。角色变更即时落库，下一条入站消息立即生效。

### 5.4 群清理

当系统掌握确定性移出证据时自动清理；协议没有上报移出事件时，操作管理员可以在页面点击“确认已移出并清理”。页面不得把“刷新状态”描述成协议不支持的完整群列表拉取。

## 6. 微信命令

保留并补充以下命令：

- `/help`、`/commands`：列出完整命令及所需角色。
- `/status`、`/whoami`：查看连接、身份和有效权限。
- `/rooms`、`/room`、`/room current`：聊天室选择与查询。
- `/sessions`、`/use`：选择已配置模型会话。
- `/models`：列出可用模型和 Provider。
- `/files`、`/file`：文件查询、读取与写入。
- `/members`：查看当前群已识别成员与角色。
- `/member <成员ID> operator|chat|none`：仅操作管理员可设置角色。
- `/group current`：查看当前群绑定和同步状态。
- `/group detach`：仅操作管理员可解除当前群并清理。

群内命令必须明确 `@ClawBot`；私聊不要求 @。不提供 `/claim`。

## 7. 授权决策

运行时按以下顺序判定：

1. 登录账号在线。
2. 群绑定存在且启用。
3. 群、成员与 mention 身份完整。
4. 群消息明确 `@ClawBot`。
5. 解析操作管理员或成员角色。
6. 角色允许请求能力。
7. 聊天室授权允许该能力。
8. 写操作需要的审批已满足。

任何一步失败都生成结构化结果并回写调用方；相同失败在限流窗口内不重复调度，防止模型或工具递归调用。

## 8. 退群与级联清理

确定性移出证据包括：

- provider 上报明确的机器人移出群事件；
- 对该群发送消息返回确定性的“群不存在/机器人不在群/无发送权限”终态错误；
- 操作管理员在页面确认已移出；
- 操作管理员执行 `/group detach`。

清理操作必须在单个数据库事务中：

- 删除群绑定；
- 删除该群成员授权；
- 终止该群未发送 outbox；
- 删除该群的临时路由状态；
- 写入不可执行的审计墓碑。

审计墓碑和历史成功/失败记录保留，避免清理后无法追溯。没有确定性证据时只标记 `sync_limited`，不自动删除。

## 9. 错误处理与安全

- 成员身份缺失：拒绝调度，记录 `group_member_identity_missing`。
- mention 不可确认：静默忽略并记录 `bot_mention_unconfirmed`。
- 无权限：不调度，按群和成员限流提示。
- 能力不足：返回 `capability_denied`，不自动升级角色。
- 聊天室授权不足：返回 `room_permission_denied`。
- 重复失败：触发现有 repeated-failure guard，不递归重试。
- provider 离线：群状态显示同步中断，不错误清理数据。

## 10. 验收标准

### 10.1 自动化验证

- 官方 `group_id + from_user_id` 消息能正确识别群成员。
- 群成员默认无权限。
- 操作管理员、操作员、聊天成员和无权限的能力矩阵正确。
- 未 @ 群消息不调度。
- 身份或 mention 不完整时 fail-closed。
- 群清理在单事务内级联，并保留审计墓碑。
- `/help` 显示全部新增命令和角色要求。
- `cargo build -p coolzhu-web-console --offline` 通过。

### 10.2 Computer Use 与真实微信验证

1. 在 Tauri“微信连接”窗口认领操作管理员。
2. 手机微信把 ClawBot 加入测试群，群内发送首条 @ 消息。
3. 窗口自动显示群和首个已识别成员。
4. 聊天成员 @ 后得到对话回复，文件和工具请求被拒绝。
5. 操作员可以调用工具和读写文件，任务与审批被拒绝。
6. 无权限成员不触发模型或工具，只收到限流提示。
7. 操作管理员的任务与审批按聊天室授权执行。
8. 未 @ 消息保持静默。
9. 从手机微信移出 ClawBot，验证明确事件或终态错误触发自动清理。
10. 协议未上报移出事件时，通过页面“确认已移出并清理”验证兜底路径。

真实测试需要至少两个非管理员微信成员，以覆盖操作员、聊天成员和无权限角色切换。

## 11. 非目标

- 不承诺主动读取完整微信群成员名册。
- 不通过桌面自动化或注入方式操作微信加群、退群。
- 不把 ClawBot 操作管理员等同于微信群主或群管理员。
- 不允许成员角色绕过聊天室授权。
- 不以无消息时长推断 ClawBot 已被移出群。
