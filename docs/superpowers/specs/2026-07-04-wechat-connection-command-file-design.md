# 微信连接：命令、文件与远程任务设计

- 日期：2026-07-04
- 状态：用户已确认
- 方案：在现有 web-console、Sidecar 和 iLink Provider 内增加确定性控制层
- 对外名称：微信连接
- 内部兼容：现有 `clawbot` 路由、数据字段和类型名暂不做全量迁移

## 1. 背景

当前实现已经具备二维码登录、登录状态轮询、联系人绑定表单、文本收发和基础命令解析，但仍存在以下缺口：

1. 微信侧无法可靠枚举并选择真实聊天室、模型会话和模型。
2. `/rooms`、`/sessions`、`/tasks`、`/status` 等命令仍有占位返回，未查询实时运行数据。
3. Sidecar 和 iLink Provider 目前主要处理文本，尚无完整的入站附件、出站文件和任务产物回传闭环。
4. 群聊只有粗粒度绑定，缺少按群成员和能力维度控制的白名单门禁。
5. 命令失败、Provider 失败和模型工具调用之间缺少统一终态，存在静默失败或重复调用风险。
6. 界面仍暴露 ClawBot 文案，且连接、绑定、文件、审批、任务、事件分散。

本设计把微信作为 coolzhu agent 的受控移动入口，而不是独立模型会话。微信消息必须继续使用 coolzhu 的聊天室、会话、模型、Agent、工作区和授权配置。

## 2. 目标

### 2.1 P0 必须完成

1. 对外界面、帮助和错误文案统一命名为“微信连接”。
2. 扫码登录在当前窗口内完成，登录成功后自动切换为真实账号和在线状态。
3. 微信侧能够选择聊天室、模型会话、模型、目标 Agent 和工作区。
4. 所有独立斜杠命令通过确定性控制层执行，不交给模型猜测。
5. 微信侧能够读取文件、上传并写入文件、写入文本以及获得任务完成后的文件。
6. 文件写入和工具调用继承聊天室授权，并叠加群聊成员白名单。
7. `/status` 能报告登录、Provider、Sidecar、路由、会话、模型、任务和最近错误。
8. 所有请求都获得成功或失败终态，失败不得驱动模型递归重试。
9. 使用真实控制台和真实微信完成端到端验收。

### 2.2 后续扩展

1. 图片、截图和语音作为模型输入。
2. 微信推送 Diff、测试报告、终端摘要和截图。
3. 定时任务、任务订阅、完成通知和临时授权。
4. 多微信账号和多执行节点。

### 2.3 非目标

1. 本轮不把现有内部 `clawbot` 标识一次性重命名，避免破坏持久化数据和现有脚本。
2. 本轮不把所有自然语言请求都转换为管理命令；只有独立斜杠命令走确定性通道。
3. 本轮不允许微信端绕过本机工作区、工具策略、聊天室授权或审批机制。

## 4. 总体架构

采用方案 A：保留当前 web-console、Sidecar 和 iLink Provider，在模型会话前增加确定性控制层。

消息主链路：

```text
微信联系人/群聊
  -> iLink Provider
  -> Sidecar 入站队列与去重
  -> 消息标准化（账号、群、发送人、@对象、附件、请求 ID）
  -> 联系人/群聊白名单与能力门禁
  -> 命令路由 或 模型会话路由
  -> 命令/模型/工具/文件/审批/任务服务
  -> 统一事件与终态回执
  -> Sidecar 持久发件箱
  -> iLink Provider 文本或媒体发送
  -> 微信
```

### 4.1 模块边界

1. **消息标准化器**
   - 将 Provider 原始消息转换为稳定的入站消息结构。
   - 生成幂等请求 ID，保留 `context_token`、发送人稳定 ID、群 ID、@对象和附件描述。

2. **授权门禁**
   - 判断群是否启用、发送人是否在白名单、消息是否满足 @规则、所需能力是否允许。
   - 合并微信群成员能力、联系人绑定和 coolzhu 聊天室授权。

3. **确定性命令路由器**
   - 仅接收独立、以 `/` 开头的命令消息。
   - 完成解析、参数校验、实时目录查询、权限校验和明确结果返回。
   - 命令文本不再进入模型上下文。

4. **模型会话路由器**
   - 普通消息按照当前绑定进入 coolzhu 聊天室、会话、模型和目标 Agent。
   - 绑定不存在或失效时返回可操作错误，不猜测默认目标。

5. **文件与产物服务**
   - 统一处理本地文件、微信附件、任务产物、路径授权、大小限制、校验值和传输状态。

6. **审批服务**
   - 创建不可变操作快照，保存请求人、聊天室、路径、命令、工作目录、权限依据和有效期。
   - 处理允许一次、当前聊天室持续允许和拒绝。

7. **任务与状态服务**
   - 查询、继续、停止和干预任务。
   - 聚合登录、Provider、Sidecar、路由、会话、模型、队列和错误状态。

8. **统一出站服务**
   - 支持文本、文件和后续媒体类型。
   - 通过持久发件箱保证断线恢复和幂等补发。

`main.rs` 仅保留 HTTP 路由和服务编排。新逻辑不得继续堆入巨型 handler；命令、授权、文件和状态应拆分为边界明确的 Rust 模块。Sidecar 负责可靠队列，Provider 只负责 iLink 协议适配。

## 5. 授权模型

### 5.1 群聊强制门禁

每条群消息按以下顺序校验：

1. 微信群已在控制台启用。
2. 原始发送人的稳定微信 ID 位于该群白名单。
3. 普通消息明确 @当前微信机器人账号；独立管理命令可按群配置允许免 @。
4. 发送人具有本次操作需要的能力。
5. 当前绑定的 coolzhu 聊天室授权允许本次操作。

任一步失败都不得调用模型或工具。默认静默忽略，控制台可配置回复“无权限”；无论是否回复，都写入安全审计事件。

### 5.2 能力预设

| 预设 | 能力 |
|---|---|
| 聊天成员 | 普通聊天、帮助、身份和状态查询 |
| 协作者 | 聊天、只读工具、授权工作区文件读取 |
| 操作者 | 继承聊天室授权调用工具、写文件、控制任务 |
| 管理员 | 管理绑定、白名单、授权和审批 |

控制台允许在预设基础上按能力开关细分：`chat`、`status`、`tools.read`、`tools.write`、`files.read`、`files.write`、`tasks.control`、`approvals.resolve`、`bindings.admin`。

### 5.3 聊天室授权继承

- 普通聊天室：读取限制在授权目录；写入、覆盖和危险工具调用需要审批。
- `full-access` 聊天室：允许白名单操作者在授权目录内自动读写。
- 删除、授权目录之外的路径、凭据和敏感配置仍需审批或直接拒绝。
- 群管理员身份不自动获得 coolzhu 管理权限。
- 私聊白名单和群聊白名单分开保存。
- 联系人改名不影响授权主体；转发、引用和附件始终按原发送人稳定 ID 校验。

## 6. 命令协议

### 6.1 通用规则

1. 独立命令必须以 `/` 开头，命令和参数使用空格分隔。
2. 编号选择只能引用当前请求返回的短期目录快照，过期后要求重新查询。
3. 每次成功切换都返回当前聊天室、会话、模型、Agent 和工作区摘要。
4. 未识别命令返回帮助，不回退为模型消息。
5. 普通非命令消息发送给当前已验证的绑定目标。

### 6.2 命令目录

| 分类 | 命令 |
|---|---|
| 帮助 | `/help [主题]`、`/commands` |
| 身份与状态 | `/status [detail]`、`/ping`、`/whoami` |
| 聊天室 | `/rooms [关键词]`、`/room <编号或ID>`、`/room current` |
| 会话 | `/sessions`、`/use <编号或ID>`、`/new [模型]`、`/compact` |
| 模型 | `/models [provider]`、`/model <编号或名称>`、`/model status` |
| Agent | `/targets`、`/target <编号或ID>`、`/target clear` |
| 工作区 | `/workspace`、`/workspace <编号>`、`/cwd` |
| 任务 | `/tasks`、`/task <ID>`、`/continue <ID>`、`/stop` |
| 运行中干预 | `/steer <补充指令>`、`/queue status` |
| 文件 | `/file list [路径]`、`/file info <路径>`、`/file get <路径>`、`/file put <路径>`、`/file write <路径>` |
| 产物 | `/artifact latest`、`/artifact <任务或文件>`、`/diff [任务ID]`、`/tests [任务ID]` |
| 权限 | `/permissions`、`/approvals`、`/approve <ID> once|always`、`/deny <ID>` |
| 诊断 | `/errors`、`/logs [条数]`、`/reconnect` |
| 通知 | `/notify on|off`、`/notify status` |

### 6.3 `/status detail` 内容

1. 微信账号和登录状态。
2. Provider、Sidecar 和消息通道健康状态及最近心跳。
3. 当前联系人或群、聊天室、会话、模型、Agent 和工作区。
4. 当前聊天室授权、群成员能力和 @规则。
5. 当前任务、待审批数、发件箱积压和最近终态错误。
6. 状态生成时间和请求 ID。

## 7. 文件与产物闭环

### 7.1 读取并回传

`/file get <路径>` 执行以下流程：

1. 解析为规范化绝对路径。
2. 校验工作区根、聊天室授权、发送人能力和敏感文件规则。
3. 读取文件元数据和大小。
4. 小文本可附带短预览；最终始终支持作为微信文件发送。
5. 保存传输记录、校验值和终态。

### 7.2 上传并写入

`/file put <目标路径>` 使用同一条微信消息或紧随其后的一个附件作为内容。流程为：

1. Provider 获取并解密附件，Sidecar 生成入站附件记录。
2. 文件服务校验类型、大小、目标路径和授权。
3. 普通聊天室创建审批；`full-access` 聊天室可在授权目录内直接写入。
4. 覆盖前记录原文件摘要，审批快照绑定目标路径和附件校验值。
5. 完成后返回写入结果，并可按配置回传最终文件。

### 7.3 写入文本

`/file write <目标路径>` 的正文位于命令下一行。命令和正文作为一个不可分割请求保存，防止审批后正文被替换。

### 7.4 任务产物

任务结果可以登记一个或多个产物。`/artifact latest` 返回当前会话最近成功任务的默认产物；存在多个产物时先返回编号列表，用户再选择。自动回传只发送任务明确登记的产物，不扫描整个工作区。

### 7.5 限制

1. 文件大小和允许类型由配置控制，超限返回明确错误。
2. 凭据、会话配置、私钥、Cookie、令牌和软件当前模型会话配置默认禁止外发。
3. 路径必须经过规范化后再判断授权根，拒绝符号链接和 `..` 绕过。
4. 文件与凭据保留在本机，仅被明确请求并授权的产物上传到微信。

## 8. 请求状态、失败与递归看护

每个入站请求使用唯一 `request_id`，状态机固定为：

```text
received
  -> authorized
  -> running | awaiting_approval
  -> succeeded | failed | denied | cancelled
```

规则：

1. 终态不可重新进入 `running`。
2. 同一微信消息 ID 和请求摘要重复到达时返回已有结果，不重复执行。
3. 只允许网络发送、长轮询和临时 Provider 错误做有限重试，默认最多两次并使用退避。
4. 命令解析失败、授权失败、用户拒绝和业务执行失败不自动重试。
5. 失败结果不得重新投递给模型形成新回合。
6. 模型工具调用若引用同一 `request_id` 的失败操作，控制层直接返回既有失败和建议动作。
7. 每次调用至少产生“已接收”和一个终态回执；长任务可增加有限的里程碑进度。
8. Provider 或 Sidecar 离线时，已完成结果进入持久发件箱；恢复后按幂等 ID 补发。

## 9. 前端窗口设计

### 9.1 命名

1. 顶部标签、窗口标题、ARIA 标签、帮助、状态、错误和空状态均使用“微信连接”。
2. 用户可见区域不再显示 ClawBot。
3. 实际被 @的微信账号昵称来自登录账号资料或可配置显示名，不与产品标题绑定。

### 9.2 布局

保持现有项目的上下结构：

1. 顶部：窗口名称、登录账号、总连接状态和刷新入口。
2. 中间标签页眉：概览、联系人与绑定、群聊白名单、会话与模型、文件与产物、审批与任务、事件与诊断。
3. 主体概览：左侧登录和安全摘要，中间当前路由、白名单与任务，右侧待处理、快捷操作和最近异常。
4. 底部：事件流、队列、待审批和最近同步时间。

### 9.3 状态化二维码卡片

1. 未登录或凭据失效：在左栏当前卡片内显示二维码、过期时间、刷新和取消操作。
2. 等待扫码：后台单实例轮询，刷新二维码不得并发创建多次登录。
3. 已扫码确认中：显示确认状态，不继续生成新二维码。
4. 在线：同一卡片切换为真实账号、Provider、Sidecar 和消息通道状态，二维码隐藏。
5. 短暂断线：先自动重连；只有凭据失效才重新进入二维码状态。
6. 前端状态、Provider 状态和真实登录账号来自同一后端快照。

### 9.4 群聊白名单界面

1. 选择微信群后展示成员搜索、已授权成员和能力摘要。
2. 支持能力预设、细粒度能力、授权到期时间、批量添加和移除。
3. 明确显示默认拒绝、是否必须 @、未授权消息回复策略。
4. 保存前预览有效权限：成员能力与聊天室授权取交集。

## 10. 持久化和 API

需要持久化以下对象：

1. 微信账号和联系人/群绑定。
2. 群聊白名单成员、能力、到期时间和修改审计。
3. 当前聊天室、会话、模型、Agent 和工作区绑定。
4. 入站请求、状态机、终态和幂等键。
5. 审批请求和不可变操作快照。
6. 入站附件、出站文件、任务产物和传输状态。
7. 持久发件箱、重试次数和最后错误。

现有绑定数据通过向后兼容的默认值升级：旧联系人绑定保留；旧群绑定中的 `allowlisted=true` 不自动授权群内所有成员，管理员必须显式添加群成员白名单。

API 按资源分组，页面不得依赖巨型聚合响应完成所有修改：

- 登录与状态快照
- 联系人、群和绑定
- 群成员白名单与能力
- 实时聊天室、会话、模型、Agent 和工作区目录
- 命令预览与执行
- 文件、附件和产物
- 审批与任务
- 事件、发件箱和诊断

## 11. 验收标准

### 11.1 基础自动化验证

1. 命令解析与目录编号快照。
2. 群启用、成员白名单、@规则和能力交集。
3. 聊天室授权继承、敏感文件和路径越界。
4. 请求状态机、幂等、终态锁定和有限重试。
5. Sidecar 文本/文件发件箱和 Provider 媒体请求转换。
6. web-console 与 Sidecar 离线构建及目标测试通过。

自动化测试保持行为导向，不为 UI 文案或实现细节建立大量脆弱断言。

### 11.2 真实控制台与微信验收

所有用户可见功能最终使用 Computer Use 和真实微信验证：

1. 未登录时内联显示二维码；扫码后自动显示账号和在线状态并隐藏二维码。
2. 微信侧列出并切换真实聊天室、会话和模型，控制台同步显示。
3. 未在群白名单的成员 @机器人时不调用模型和工具。
4. 聊天成员能够对话但不能调用未授权工具。
5. 操作者在聊天室授权范围内成功调用工具。
6. `/status detail` 返回连接、路由、权限、任务和错误摘要。
7. `/file get` 返回真实文件。
8. 微信附件通过 `/file put` 写入授权路径并返回完成后的文件。
9. 普通聊天室写入触发审批，批准后执行；拒绝后终止。
10. Provider 断线后结果进入发件箱，恢复后只补发一次。
11. 故意制造业务失败，微信与控制台都显示同一终态，模型不递归调用。

## 12. 实施分段

1. **阶段一：控制层与实时目录**
   - 统一命名、模块拆分、授权门禁、实时聊天室/会话/模型查询、命令终态和状态命令。
2. **阶段二：文件、媒体和审批**
   - Provider/Sidecar 媒体契约、入站附件、出站文件、路径授权、审批和产物回传。
3. **阶段三：完整窗口与任务控制**
   - 状态化二维码、标签页、白名单编辑、文件中心、审批任务和诊断事件。
4. **阶段四：真实闭环与加固**
   - 真实微信、真实控制台、断线恢复、失败终态、敏感文件和安装包回归。

每个阶段开始前先备份相关源码目录；每个阶段结束必须通过目标构建、基础测试和对应的真实前端验收，再进入下一阶段。

## 13. 回滚原则

1. 数据结构只做向后兼容扩展，避免破坏既有绑定。
2. 文件和媒体能力使用功能开关；出现 Provider 协议异常时可以回退为文本通道。
3. 保留现有 `/room`、`/use`、`/status` 调用形式和旧 API 兼容层，直到新路径完成真实验证。
4. 风险修改前保留源码备份和配置快照；安装包不得包含当前模型会话配置、凭据和微信登录凭证。
