# 微信连接已有会话与聊天室路由设计

日期：2026-07-04

## 目标

微信连接只负责把联系人或群聊绑定到已经配置好的 coolzhu 聊天室和模型会话。微信命令不得创建、复制、删除模型会话，也不得修改 Provider 配置。

`/new` 保留为兼容命令，但语义与 `/use` 相同：选择一个已有会话作为后续消息的发送对象。它不创建会话对象、不清空消息历史，也不重置模型上下文。

## 选择身份与歧义规则

会话以 `session-id` 为唯一身份。模型名和 Provider 名只用于显示，绝不作为唯一路由键，因为不同 Provider 可以配置同名模型。

`/sessions` 返回当前已配置会话的编号、会话名称、Provider、模型和 session-id，并为当前微信账号与联系人保存一份短期目录快照。

`/use <选择器>` 与 `/new <选择器>` 按以下顺序解析：

1. 数字：解析为最近一次 `/sessions` 快照中的编号，并再次确认对应 session-id 仍存在。
2. 完整 session-id：直接匹配当前会话存储。
3. 会话名称：仅接受大小写不敏感的精确匹配；只有唯一结果时才成功。
4. 其他输入：拒绝并提示先发送 `/sessions`。不得回退到模型名、Provider 名或当前活动会话。

名称重复时返回所有候选项的编号、Provider、模型与 session-id，要求用户改用编号或 session-id。`/new` 或 `/use` 未提供参数时只返回操作提示，不改变绑定。

聊天室采用相同原则：`/rooms` 生成编号快照，`/room <编号|room-id|唯一聊天室名>` 只选择已有聊天室。

## 命令契约

- `/sessions`：列出已有会话并生成目录快照。
- `/use <选择器>`：选择已有会话，保存真实 session-id。
- `/new <选择器>`：`/use` 的兼容别名；回复中说明未创建新会话。
- `/models`：只展示模型目录，不参与会话路由选择。
- `/rooms`：列出已有聊天室并生成目录快照。
- `/room <选择器>`：选择已有聊天室，保存真实 room-id。
- `/status`：展示当前绑定的聊天室名称/ID、会话名称、Provider、模型和 session-id；绑定失效时明确标记。

普通微信消息只在聊天室和会话绑定都有效时进入模型调用。任一绑定为空、失效或歧义时都拒绝调度，并返回可执行的恢复步骤，避免误投递。

## 前端管理页

“微信连接”页面将自由文本字段改为受控选择：

- “coolzhu 聊天室”使用聊天室下拉框，选项显示聊天室名称，值保存 room-id。
- “会话 / 模型”改名为“发送到会话”，使用会话下拉框；选项显示“会话名称 — Provider / 模型”，值保存 session-id。
- 绑定卡片同时显示可读名称和稳定 ID，便于诊断实际路由。
- 已保存的旧值如果能唯一匹配会话名称或聊天室名称，则在加载或保存时规范化为真实 ID。
- 旧值如果只匹配模型名、存在多个同名对象或已不存在，则标记为“绑定失效”，要求用户重新选择，不做自动猜测。

前端保存接口和微信命令最终都只持久化稳定 ID，确保两条配置路径行为一致。

## 数据流与状态变化

1. 用户通过前端下拉框，或在微信发送 `/sessions` 后使用 `/use`、`/new` 选择会话。
2. 选择器解析器得到唯一 session-id，并确认该会话仍存在。
3. ClawBot 更新当前账号与联系人绑定的 `default_session_id`，不修改会话存储中的对象数量、配置和历史。
4. 普通消息读取绑定中的 room-id 与 session-id，按聊天室授权校验后发送给所选会话。
5. 命令成功或失败均通过 outbox 回执微信；失败不会自动重试选择，也不会回退到其他会话。

## 错误处理

- 未先获取编号目录：提示发送 `/sessions` 或 `/rooms`。
- 编号越界或快照过期：提示刷新目录，不使用旧编号。
- session-id 或 room-id 已删除：标记绑定失效并提示重新选择。
- 会话名或聊天室名重复：返回候选列表，不选择第一个结果。
- 模型名输入：提示模型名不能唯一标识会话，并返回 `/sessions` 的操作步骤。
- 会话已达上限：选择操作与上限无关，不应返回会话上限错误。

## 非目标

- 不新增模型会话。
- 不清理或覆盖会话历史。
- 不按 Provider 与模型组合临时构造会话。
- 不自动选择当前活动会话。
- 不修改现有聊天室授权、联系人白名单和工具授权模型。

## 验收标准

1. 已有 10 个会话时执行 `/new <有效编号>` 成功，执行前后会话总数保持 10。
2. 两个 Provider 配置同名模型时，通过 `/sessions` 编号或 session-id 能稳定选择目标会话。
3. 唯一会话名可以选择；重复会话名返回歧义错误且绑定不变。
4. `/new` 与 `/use` 更新相同绑定字段；`/new` 回执明确说明没有创建新会话。
5. `/new` 无参数、模型名、过期编号和已删除 session-id 均不改变绑定，并给出恢复步骤。
6. 前端会话和聊天室控件只保存稳定 ID，刷新页面后仍显示正确名称、Provider 与模型。
7. 真实微信闭环依次通过：`/sessions`、`/new <编号>`、`/status`、普通消息；普通消息和回复均落入所选聊天室与会话。
8. ClawBot 回归测试和 `cargo build -p coolzhu-web-console --offline` 通过，随后使用 Computer Use 验证真实前端。
