## 改动（modules/gui-web/packages/web-console/src/main.rs）

   （含 Mutex 锁 + 配置落盘，避免阻塞 async executor）；首个 tick 立即触发，补偿停机期间到期项。
3. **main() 注册**：`start_showui_service` 之后加 `spawn_scheduled_task_scheduler();`。
4. **防漂移对齐** `next_aligned_run_at(base, now, interval_ms)`：
   周期任务重排由"执行时刻 + 间隔"改为"**基于原计划时刻**对齐到 now 之后第一个触发点"，
   消除执行延迟累积漂移；错过多周期时一次跳到最近未来点（misfire = 跳过堆积，不补跑）。O(1) 防溢出。
5. **单元测试** `scheduler_align_tests`（5 个）：准点对齐 / 延迟不漂移 / 错过跳过 / 严格大于 now / 零间隔安全。

## 续（同日）：挂钟计划模型（每天 / 每周 HH:MM，本地时区）

### 方案
零新依赖：前端传时区分钟偏移 `tz_offset_minutes`（东八区 +480），后端纯算术算下一个本地挂钟触发点（无需 chrono）。

### 改动
- **结构**：`ConfigScheduledTask` + `TaskScheduleCreateRequest` 增 `schedule_kind`(once/interval/daily/weekly)、`wall_hour`、`wall_minute`、`weekdays`(0=周日..6=周六)、`tz_offset_minutes`（均 `#[serde(default)]` 兼容旧数据）。
- **算法**：`next_wallclock_fire(now, tz_offset, hour, minute, weekdays)`——本地天对齐 + 星期匹配，返回严格晚于 now 的下一个挂钟时刻（UTC ms）。epoch day0=周四，weekday=(day+4)%7。
- **创建**：daily/weekly 用挂钟算首个 `run_at_ms`，`interval_ms=None`。
- **重排**：`run_due_task_schedules_once` 中 daily/weekly 按挂钟重算下次；interval 仍走防漂移对齐。
- **前端**：表单加"计划类型 + 时刻 + 星期多选 + 间隔"，按类型显隐；payload 传 `-getTimezoneOffset()`；列表渲染可读描述（"每天 10:00" / "每周周一、周三 09:30"）。

### 验证
- `cargo test ... schedule`：**11 passed**（含 4 挂钟单测：当天/次日/每周指定星期/严格大于 now）。
- `node --check app.js`：exit 0（无语法错误）。
- 端到端（实跑 8765）：`daily 10:00` → 下次 2026-06-07 10:00:00 UTC+8；`weekly 周一/周三 09:30` → 下次 2026-06-08 09:30:00（Monday）。星期与时区均正确。

> 至此"每天上午 10 点总结 Top10 新闻"可在 GUI 直接配置：计划类型选"每天"、时刻 10:00、填内容、选目标会话即可。

## 续2（同日）：投递即执行（闭环到产出）

### 方案
用户选定"完整自动执行，按 task.permissions 门控"。`deliver_scheduled_task` 不再只注入一条 user 消息，
而是复用聊天主链路 `api_chat_send`：构造一次"用户向目标会话 Agent 发送任务内容"，触发 LLM 产出 +
工具按既有权限逻辑执行 + user/assistant 双向持久化。

### 改动
- `deliver_scheduled_task` → `async`，构造 `SendMessageRequest`（session_id=target_session_id、target_agent_ids=[target_session_id]、text=content）调 `api_chat_send`。会话 id 即 Agent id（`default_agent_sessions` 由 `sessions` 映射）。
- 链路全 async 化：`run_due_task_schedules_once` / 路由 / 后台调度器均改 `.await`；调度器去掉 `spawn_blocking`（投递会调 LLM）。
- 锁不跨 await：会话校验锁在独立块内释放后再 `.await`。

### 验证
- `cargo test ... schedule`：**11 passed**（`task_schedule_run_due` 现走 `api_chat_send` fallback 链路，断言仍成立：user 消息经 `persist_chat_dispatch` 落入会话）。
- 端到端（实跑 8765）：建 `run_at_ms=now` 任务、**不点 run-due**，后台 tick 自动 `executed`，目标会话新增 **assistant 回复**（lastRoles=`[...,user,assistant]`）——Agent 真正处理并产出，而非仅留言。

### 安全说明
- 工具/写操作沿用 `api_chat_send` 链路既有的权限与执行逻辑。
- ✅ **task.permissions 精确门控（已补）**：`deliver_scheduled_task` 执行期间按 `task.permissions` 临时授予目标会话权限、执行后恢复——含 "full-access" 时临时 `record_session_grant_with_ttl(session, "*", full_access=true)`（`session_grants` 为内存 map、不落盘），执行后仅移除**本任务临时授予**的项（`granted_for_task` 标志，用户既有授权不动）；任务不带该权限时写操作仍被链路 gate（execute=false，仅规划）。调度器串行执行，无并发/持久化副作用。dev_open 全局开关开启时仍整体放行（开发模式既有行为）。
- 后台自动调 LLM 有成本；请求幂等窗口短，不影响每日触发。
- 副作用：验证往 `mario-demo` 注入过一问一答（demo 会话，可忽略）。

> **闭环完成**：定时任务（挂钟自动触发）→ 投递目标会话 → Agent 自动产出。"每天 10 点总结新闻"端到端可用。
