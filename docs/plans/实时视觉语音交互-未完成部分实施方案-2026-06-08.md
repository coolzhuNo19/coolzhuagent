## 三、实施方案

### A. 视觉理解层：会话可配 + 总览可选（不固化任何模型）【P0，本周可落】

**目标**：视觉理解模型**不写死 agnes**；任意多模态会话（agnes-2.0-flash / glm-4.6v / 云端/本地 VLM）
均可在会话配置中标记为"视觉模型"，并在总览中被选中为"当前视觉理解模型"，便于随时更换。

**后端现状（已具备，无需大改）**
- `store.state.active_vision_session_id`：当前视觉理解会话 id（sqlite 持久，删会话自动清理）。
- 设置入口（main.rs ~7084-7114）：校验 `is_understanding_model_type(model_type)` 后写入 active id。
- `is_understanding_model_type`：判定 vision / multimodal 类 model_type 为视觉理解候选。
- `model_type` 白名单已含 `vision` / `multimodal`（本日修复 image 后白名单完整）。

**需补（前端 + 小后端）**
1. **会话配置**（app.js `renderModelTypeSelect`）：在已有「文本/图片生成/视频生成」基础上，
   增加「视觉理解（vision / multimodal）」选项；选中后 PATCH 会话 `model_type=multimodal`。
2. **总览「视觉理解模型」选择器**：
   - 列出所有 `is_understanding_model_type` 候选会话（含云端 agnes/glm + 本地 VLM）；
   - 选中 → `POST /api/config/vision-session`（或复用现有设置 API）→ `active_vision_session_id`；
   - 显示当前选中项 + 一键切换。
3. **路由**：视觉理解请求（描述屏幕 / 看图，纯理解 gate 已修）默认走 `active_vision_session_id` 会话；
   聊天室带图请求仍可定向到指定多模态会话。

**换模型流程**：总览下拉改选另一会话即可，**零代码改动、零固化**。
- 例：默认 agnes-2.0-flash → 改选 glm-4.6v-flash → 改选未来任意多模态会话。

**验收**
- 会话配置可把 agnes/glm 会话标为视觉理解；总览能选中并切换；
- 选中 agnes → "描述当前屏幕"由 agnes 看图回答、**不触发 computer-use**；改选 glm → 由 glm 回答；
- 重启后选择持久（sqlite）。

### B. 全双工低延迟流式：4 个 readiness gate【P2，依赖 provider 能力，逐个推进】

当前 `realtime_streaming_risk_with_capabilities` 自评默认全 not-ready → `HALF_DUPLEX_GUARDED`。逐项：

| Gate | 现状 | 实施方案 |
|---|---|---|
| `provider_native_partial_asr` | turn-based 本地 STT | 接 provider 流式 STT（streaming ASR）输出 partial，置 `stt_transport=PROVIDER_NATIVE` |
| `far_end_reference_aec` | browser constraints | AudioWorklet 远端参考回声消除（far-end reference），置 `aec_mode=FAR_END_REFERENCE` |
| `realtime_model_adapter` | local HTTP bridge(guarded) | 统一 provider-native realtime session（token+音频+中断一体），置 `provider_adapter=REALTIME_PROVIDER_ADAPTER` |
| `streaming_tts_output` | segmented queue + new Audio | 流式 chunked TTS + 配 `audio.realtime.streaming_tts_url`，置 `tts_transport=CHUNKED_STREAM` |

- 四项全 ready → `full_streaming_ready=true` → `recommended_mode=FULL_STREAMING`（真·边说边听边打断）。
- 建议顺序：流式 TTS（体验提升最直观）→ provider 原生 partial ASR → 实时模型适配器 → 远端 AEC。

### C. 实时视觉理解联动【P1】

- **分工**：UI-DETR(CPU) 出**元素框 + 坐标**（高频）；视觉理解会话出**屏幕语义/意图**（低频、云端）。
- 实时循环：截图 → UI-DETR 元素表（实时）；**按需**（用户提问/关键帧）调 `active_vision_session_id`
  会话做语义理解，把"元素坐标 + 语义描述"合并给上层决策/语音播报。
- 与语音联动：语音问"屏幕上有什么/帮我点 X" → 理解会话给语义 + UI-DETR 给坐标 → barge-in/动作链。
