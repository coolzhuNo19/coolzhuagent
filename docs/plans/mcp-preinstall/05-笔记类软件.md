# 05 · 笔记类软件 MCP 预装调试方案

> 类别：个人知识库 / 笔记（Obsidian 等）。配合总纲使用。

## 一、类别概述
让 AI 通过 MCP 读写、搜索、精修笔记：列文件、全文搜索、创建/编辑笔记、改 tag/frontmatter，
把笔记库当作"连接的知识图谱"做检索与整理。生态以 **Obsidian** 最成熟。

## 二、候选 MCP / 软件清单

| 项目 | 软件 | 传输 | 成熟度 | 说明 |
| --- | --- | --- | --- | --- |
| `cyanheads/obsidian-mcp-server` | Obsidian | stdio | 高 | 经 Local REST API 插件，14 工具（读/写/管理/命令分组），可精修 tag/frontmatter |
| `aaronsb/obsidian-mcp-plugin` | Obsidian | stdio/HTTP | 高 | 语义操作 + 图谱遍历，HTTP 传输 |
| `otaviocc/ObsidianMCPServer` | Obsidian | stdio | 中-高 | 读/写/搜索/管理笔记 |
| `roelven/obsidian-mcp-server` | Obsidian | stdio | 中 | 经 CouchDB LiveSync，协议版本 2025-03-26 |
| （延伸）Logseq / Notion 等 | 其他笔记 | stdio/HTTP | 中 | 各有社区 MCP，可二期纳入 |

## 三、推荐预装组合
- **首选**：Obsidian + Local REST API 插件 + `cyanheads/obsidian-mcp-server`（工具齐、专用工具比"指目录"更可靠）。
- **图谱/语义向**：`aaronsb/obsidian-mcp-plugin`。

## 四、预装方式（在 coolzhu 落地）
1. 宿主：Obsidian + 安装 **Local REST API** 社区插件，生成 API Key、记录端口。
2. 运行时：Node（`npx`）。
3. 注册：`mcp_servers.json` → `command: npx`，`args: ["-y", "obsidian-mcp-server"]`，
   `env: { OBSIDIAN_API_KEY, OBSIDIAN_BASE_URL }`，`transport: stdio`。
4. 自检：`tools/list` 见 list_vault_files / search_vault / create_vault_file 等。

## 五、调试与验收用例
- **只读**：列出最近笔记 / 全文搜索关键词。
- **写入（授权后）**：新建一条笔记并写入内容 → 再读回校验 → 改其 frontmatter 一个字段。

## 六、风险与注意
- Local REST API Key 是笔记库的写入凭证 → 走 env/本地配置，不外传不入 query。
- 写/删除会改真实知识库 → 先指向**测试 vault**，写操作走授权。
- 笔记库体量大时限制返回条数（部分实现默认列最近 10 条）以保性能。

## 七、参考来源
- `cyanheads/obsidian-mcp-server`、`aaronsb/obsidian-mcp-plugin`、`otaviocc/ObsidianMCPServer`、`roelven/obsidian-mcp-server`。

## 接入状态（2026-06-11，已纳入 MCP Host 预装清单）

- **包**：obsidian-mcp (npm mcp-obsidian@1.0.0, 末位参数=vault 目录)
- **连接自检**：connect 1.6s PASS（2 工具）。真实冒烟：search_notes(query=coolzhu) → 6ms 返回（示例 vault 无匹配，链路通）。改 workspace mcp_servers.json 末位参数为真实 vault 即用
- **工具数**：2
- **工具样例**：read_notes / search_notes
- 用法：`POST /api/mcp/servers/<id>/connect` → `POST /api/mcp/call`。依赖宿主/Key 的条目在 workspace `.coolzhu/mcp_servers.json` 配齐后冒烟。
