# 03 · AI 辅助应用软件开发（Android / 移动端）MCP 预装调试方案

> 类别：移动应用开发 + 设备自动化。配合总纲使用。

## 一、类别概述
让 AI 通过 MCP 控制 Android 设备/模拟器：截图、UI 检查、点击/输入、装卸应用、文件传输、自动化 QA，
辅助移动应用的开发与端到端测试。

## 二、候选 MCP / 软件清单

| 项目 | 平台 | 传输 | 成熟度 | 说明 |
| --- | --- | --- | --- | --- |
| `mobile-next/mobile-mcp` | iOS+Android（真机/模拟器） | stdio | 高 | 平台无关；结构化无障碍快照或基于截图的坐标点击，操控原生 App |
| `minhalvp/android-mcp-server` | Android（adb） | stdio | 中-高 | 经 ADB 控制设备 |
| `srmorete/adb-mcp`（TS） | Android（adb） | stdio | 中 | TypeScript ADB 桥 |
| `CursorTouch/Android-MCP` | Android | stdio | 中 | LLM agent 做 App 导航/UI 交互/自动 QA，免传统 CV 管线 |
| Google Android Management API MCP | 设备管理（企业） | HTTP | 中 | 官方设备管理参考 |

## 三、推荐预装组合
- **首选（跨端 + 稳）**：`mobile-mcp`（iOS/Android 统一，截图+无障碍快照）。
- **纯 Android 调试**：`android-mcp-server`（adb 直控）。

## 四、预装方式（在 coolzhu 落地）
1. 依赖：Android SDK Platform-Tools（`adb`）入 PATH；Node 运行时（`npx`）。
2. 设备：连真机（开启 USB 调试）或启动 AVD 模拟器；`adb devices` 应可见。
3. 注册：`mcp_servers.json` → `command: npx`，`args: ["-y", "@mobilenext/mobile-mcp"]`（按实际包名）/ 对应 server，`transport: stdio`。
4. 自检：`tools/list` 见 screenshot/list-apps/tap/input/install 等工具；先跑 `adb devices` 校验链路。

## 五、调试与验收用例
- **只读**：列出已装应用 / 截一张屏 / dump UI 层级。
- **写入（授权后）**：安装一个示例 APK → 打开 → 点击一个按钮 → 截图验证。
- **QA 闭环**：给定用例步骤，自动跑一遍并回报通过/失败。

## 六、风险与注意
- adb 可装卸应用、读写设备 → 仅连**测试设备/模拟器**，写操作走授权。
- 真机数据敏感，避免在生产/个人主力机上跑自动化。
- 不同 ROM/分辨率的坐标点击差异 → 优先无障碍快照而非纯坐标。

## 七、参考来源
- `mobile-next/mobile-mcp`、`minhalvp/android-mcp-server`、`srmorete/adb-mcp`、`CursorTouch/Android-MCP`、Google Android Management API MCP。
